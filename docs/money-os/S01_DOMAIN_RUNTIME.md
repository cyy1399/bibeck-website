# BiBeck Money OS domain runtime

S01 provides a synchronous pure domain boundary around the frozen Money Model. It does not connect a website, service, database or event workflow. Financial policies and saved data are unchanged.

## Entry point and pipeline

Import `analyzeFinancialProfile`, `moneyModelV1Bundle` and the input types from `lib/money-model/index.ts`. Call `analyzeFinancialProfile(profile, options, moneyModelV1Bundle)`. The bundle argument is mandatory; snapshot ID, observation date, monthly period, basis confirmations and inventory completeness come from the caller, not the system clock.

The facade bounds plain input and checks its structural format, verifies analysis basis and claim invariants, then invokes the frozen normalizer. Metrics, resource lineage, claim counts, flags and raw provenance remain integrated there. The same injected bundle supplies the evaluator and the output validator, including the validator's rule replay. Rule phase, order, tie-break, overrides, findings, stages, severity and mission resolution remain the original implementation. Output is validated before returning and detached from caller objects.

Resources and claims are supplied domain contracts, not inferred from missing information. S01 validates them; it does not implement a new claim-generation policy, optimal allocation producer or fulfillment service. The existing pure reference ledger remains an internal compatibility module, not a public capability.

## Results and configuration

`ok: true` returns the full frozen `DecisionOutput` plus separate normalization traces and rule diagnostics. Valid R-008 and R-015 correction projections carry `CONTRADICTORY_STATE`; financial unknowns can carry `MISSING_REQUIRED_INFORMATION` and Discover missions. Stage is distinct from severity. No action means no forced mission, not Optionality or a health certification.

`ok: false` returns a controlled error category and safe code, never financial payloads or a stack. Malformed inputs use `VALIDATION_ERROR`; invalid claim funding or invalid output uses `DOMAIN_INVARIANT_VIOLATION`; an unknown bundle uses `UNSUPPORTED_MODEL_VERSION`; unexpected faults use `INTERNAL_ERROR`. Structural basis not confirmed uses `MISSING_REQUIRED_INFORMATION` before analysis. Missing financial values with a confirmed basis normally remain UNKNOWN in a valid output instead of becoming zero.

Only `money-model-v1-freeze-cfff3150-baseline-1` is registered. Its manifest identifies the pinned commit, artifact digest, runtime/schema/output versions and `AS-001-revision-1-baseline-1`. The immutable config is explicitly injected into the normalizer. Minimum viable liquidity remains the research baseline of 1 month, with LOW confidence, not universal advice or financial-policy approval. Fabricated or copied bundles and config changes are rejected without latest-version fallback.

Old docs paths re-export the library implementation. The legacy evaluator and validator can omit the bundle to preserve historical registry revision probes; the production facade never does. Production evidence/assumption records are frozen copies, so those probes cannot change a production decision. Existing fixture context overrides and native calculation helpers remain in docs and are not production dependencies.

## Verification and limits

`tests/money-os-runtime-parity.test.mjs` reconstructs an independent read-only oracle from the pinned `cfff3150fb5e6a258596fa54caa745023bcde894` git objects. Its committed file/blob manifest is checked before loading. It compares every normalized field, metadata record, trace, DecisionOutput field and legacy diagnostic for A–F, observed updates, partial information and the existing 16 rule fixtures. A separate body comparison permits only declared relocation/configuration adapters; hand-written golden expectations are not generated by the evaluator.

The historical reference may emit lineage that fails its own validator when monthly basis is unconfirmed. Production does not repair the frozen model or certify that output; the structural-basis gate returns missing information. Parity still checks the historical normalization/evaluator/validator behavior for that case.

Dynamic safety targets, universal high-cost APR thresholds, irregular income normalization, annual expense periodization, insurance, jurisdictional tax/legal policy, liquidity haircuts, risk models, portfolio allocation and Optionality remain unsupported. B is a qualified high-cost research fixture. E cannot manufacture a savings mission. F retains UNKNOWN sustainability/allocation/goal-conflict producers and only the supported goal observation. No claim funding percentage is invented for unknown amounts, and FUNDED does not imply FULFILLED or VERIFIED_DONE.

Input and output checks are bounded to plain data, 50,000 visited nodes and depth 64; the original predicate limits remain 256 nodes/depth 32. Oversized inputs fail safely and oversized outputs are rejected, not partially certified. The historical oracle tests require Git and the pinned objects locally. Domain code has no React, Next, DOM, Node, network, auth, DB, logging or ambient-clock dependency; its dedicated ES2022 typecheck has no DOM/Node types. S00 arithmetic and its pinned body hash remain unchanged.

Run `pnpm typecheck:money-model`, `pnpm typecheck`, `pnpm lint`, `pnpm spec:validate`, `pnpm test`, and `node --experimental-strip-types tests/freeze-blocker-reproductions.mjs`. Test/build commands do not authorize a deployment. Stop after S01; no S02 parser/codec, UI, persistence, auth, API or migration is included.
